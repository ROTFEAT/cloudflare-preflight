# Native controls first

For each recommendation inspect the supported native capability first, then state exactly which meter and path it constrains. Only a real gap justifies a minimal application checkpoint, persistent logical-task budget, idempotent side effect or admission guard. Preserve correctness and essential persistence; never swallow errors, ack everything or delete work merely to lower test usage.

Structured `native_controls` records contain product, plan/backend, control name/surface, scope, official source, checked date, version conditions, current evidence, data preservation, reversibility, effect on running work, new producer coverage, propagation delay, uncovered paths and human verification. Unknown online facts remain unknown. v1 execution_status is NOT_EXECUTED or local simulation only.

Control surfaces are distinct: CPU/retry config, object-runtime deleteAlarm, consumer management pause, notification alerts, and test-only resets. None implies an account-wide monthly budget. WAF/custom-domain protection does not establish coverage of workers.dev, internal RPC, alarms, queues or S3 credentials. Unrouting/unbinding/deleting a namespace are not interchangeable with a reversible data-preserving pause. Storage/fixed charges can remain after incoming work stops. No external DO pause API is confirmed or implemented here.

Use [platform-facts.md](platform-facts.md) and the recorded primary sources. Production isolation and recovery need separate requirements and authorization; this skill only proposes controls.
