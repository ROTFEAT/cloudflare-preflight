# Trust and release boundary

The analyzer has no Cloudflare credentials and cannot publish. `gate` verifies an Ed25519 attestation, an external trust file, allowed signing key/origin/run identity, freshness, all unique rules, completed official semantic reviews, actual required test records, unchanged source/artifact/target/config/toolchain/migrations/policies/official lock and verifier fingerprint. It reruns current static/local checks so a fabricated summary cannot hide a known BLOCK. Exit codes: 0 allowed, 1 confirmed BLOCK, 2 incomplete/unapproved evidence, 3 tool invocation error. BLOCK wins over other incomplete information.

The trusted signer is an explicit authority. Protect its private key and signing workflow; a signature from an attacker-controlled signer does not establish review. Place keys and trust outside the candidate checkout. The publisher/CI verifier must be installed from a trusted immutable tool revision outside candidate code, with prepared locked dependencies. Do not execute a candidate's modified verifier with release/signing secrets. Trusted keys may assert runtime test evidence after inspecting the actual runner records; signing arbitrary candidate JSON is forbidden.

Use `attest` with complete semantic review, external `--private-key`, `--key-id`, `--origin` and `--run-id`. It regenerates the report/probe for current inputs and refuses incomplete evidence. The signer has review authority, never Cloudflare deployment credentials. CI reviewers can provide signed envelopes from a separate trusted workflow.

The publisher independently supplies `--root --config --env --artifact --builder --account --action` to `gate`, plus external `--trust` and `--attestation`. Do not copy the report's target as the publisher's intended target without validating it. Use a final config whose main points into the reviewed artifact; rollback/promotion also needs `--candidate-version`. The existing publisher consumes verified immutable bytes with bundling/building disabled. Prevent concurrent mutation between gate and publisher (an immutable CI artifact or read-only staged handoff); arbitrary mutable local workspace publication is not race-safe.

For REVIEW, provide signed approval envelopes (`approval.schema.json`) from an allowed approval role: input digest, explicit finding IDs, approver/reason/scope, expiry, compensating controls and evidence. Gate preserves REVIEW and emits ALLOW_WITH_APPROVAL. Ordinary approval cannot resolve BLOCK, missing dependencies/tests or tool errors. No hidden exemptions are supported in v1.

The repository includes a local read-only staging/publisher handoff and a GitHub Actions release example. The local analyzer rejects inherited Cloudflare credentials and awaits async publisher failures. File chmod is advisory for the same owner. The example publisher rechecks and seals each file into a Linux memfd, mounts those bytes read-only in a namespace, then invokes pinned Wrangler with bundling disabled and no custom build. Host staging changes cannot replace those consumed bytes. Credentials are loaded only by that separate publisher after the gate; host administrators and the trusted publisher remain in the trust boundary.

These examples cover only their integrated paths. Admins must separately connect or disable direct Wrangler, console, Workers Builds deploy/preview and independent CI paths. Required PR checks do not automatically gate Cloudflare-managed Builds. Never alter branch protection/account settings without the user's separate authorization.
