# Review procedure

1. Inspect release scripts/configuration as data. Identify the first remote effect, final artifact, effective environment, account/application, action, builder, migrations, routes/triggers, compatibility and pinned dependency/tool versions. Static JSONC/TOML parsing does not execute a config. A missing generated config, unsupported framework/CLI or dynamic SQL/SDK is a gap.
2. Run the trusted CLI `preflight --local-tests` with explicit candidate inputs. It snapshots bounded regular files, excludes credential files, redacts inline sensitive literals before hashing, builds a TypeScript AST/call graph and SQL candidates, reads official locked content and runs a socket-denied SQLite plan probe. For `diff --base FULL_COMMIT`, it records changes and conservatively analyzes the full local call closure. It never runs candidate build/deploy/lifecycle scripts.
3. Read the actual official context and candidate files. All P0 rules require semantic coverage. Use concrete entry→operation→resource paths, real file/line evidence and defined usage units. Review hot misses/invalid credentials, reactivation, fresh message IDs, crash windows, ineffective indexes and generated environment multiplication. For background work and public downstream calls, apply [delayed-and-origin-checks.md](delayed-and-origin-checks.md), including delayed refresh/expiry, direct-origin access and bounded remaining work after stopping. Name unsupported paths rather than treating parser absence as safety.
4. Inspect and authorize any local build/test commands separately. The bundled `scripts/sandbox.py` uses bubblewrap user/mount/network/PID namespaces, a read-only checkout, empty HOME, clean environment, credential-file masking, parent wall/RSS/process/output/disk watchdogs, and process-group termination. It fails closed when namespace isolation is unavailable. V8/Workerd need large virtual reservations, so actual tree RSS is checked separately from heap limits. The engineering runtime suite uses an explicit 1,024 MiB tree limit; ordinary sandbox commands default to 512 MiB or accept `--memory-mb`. The SQL probe separately enforces the policy memory limit up to its 256 MiB hard maximum. Use only prepared dependencies; no network installation during tests. Remote bindings fail the preflight.
5. Test budgets default to 50 events/messages, 10,000 fixture rows, 10 seconds per probe and bounded memory. Code-driven harnesses must actually charge each event/message/row and stop on exhaustion; declaring a number is not enforcement. Parent watchdogs can interrupt sync and microtask loops. Keep SQL plans separate from measured DO cursor/D1 meta rows; missing metrics stay null/unsupported. Runtime API availability and eviction restrictions follow the installed Cloudflare integration.
6. Build a `semantic-review.schema.json` record. Populate all 12 unique rule records, official reviewed file paths/digests/reasoning, actual required tests, findings and model/invocation. Never invent a passed test, fill absent metrics with zero, promote an upstream style suggestion to BLOCK without policy/evidence, or approve unknown high-risk coverage. Test runner identities and results are trusted assertions, not a proof that an arbitrary program terminates.
7. Rerun preflight with the review record. The report preserves known BLOCK, tracks official/cost results separately and lists unresolved input/tests/gaps. The trusted attestation step and independent publisher gate are described in [predeploy-gate.md](predeploy-gate.md).

Static support is deliberately narrow; see the repository coverage table. Finite-work and window-budget semantic claims need actual enforcement evidence. Use the usage vector rather than currency. If every required factor is known, give `bounded_under_assumptions` with scopes/limits and caveats; otherwise unknown or an evidenced unbounded_path. A predicted user count is an assumption, never admission control.

The CLI compares the lock with actual installed Wrangler package metadata, without running that CLI. Use `--wrangler-package /TRUSTED/node_modules/wrangler/package.json` when the authorized publisher owns the tool installation. Missing/mismatched versions are gaps. A final config's main is resolved relative to the config file. `--env default` selects top-level config; `production` selects env.production when present and top-level otherwise. The publisher must use that same dispatch.

Unknown existing/external DO activation is not a confirmed cost loop. The narrow static DO proof needs a reachable stub RPC/fetch, a local DurableObject class, constructor scheduling, alarm work and rearm. SQL schema evidence must belong to that DO; a D1 migration does not initialize it. RPC names reserved for platform alarm/lifecycle methods are not used as activation evidence. Review all remaining SDK/dispatch/production-history gaps explicitly.
